# Halloween · Día de los Muertos — the theme

Slug `halloween-dotd`. The first seasonal look built on the theme engine described in
`docs/seasonal-theme-audit.md` and operated from the admin as described in
`docs/seasonal-theme-admin.md`.

The brief in one line: *Oasis, art-directed for late October* — not a Halloween template. The
same restaurant, the same pages, the same content; a darker room, candle-light, marigolds, cut
paper, and slow motion. Nothing cartoon, nothing neon, no skulls.

---

## Palette

Every value is a remap of an existing design token, declared once in
`src/themes/halloween-dotd/theme.css` under `[data-theme='halloween-dotd']`. Components are not
edited; `bg-ivory` simply means something else while the theme is on.

| Role | Everyday token | Seasonal value | Notes |
|---|---|---|---|
| Canvas | — | `#120a12` very dark plum | Paints `<html>` too, so overscroll matches |
| Page surfaces | `ivory` `ivory-deep` `cream` `linen` | `rgb(29 16 29 / .86)` … `rgb(45 24 41 / .92)` | **Translucent** so the fixed candle glow shows through |
| Warm surface | `sand` | `#3b1526` burgundy | |
| Ink | `brown` / `brown-soft` | `#f4e7cf` bone / `#cfb58f` | 15.3:1 and 9.4:1 on the canvas |
| Action | `coral` `orange` | `#e58a2e` `#e8912c` marigold | Label stays near-black `#23110a` (7.1:1) |
| Orange text | `clay` | `#f0a548` | 8.6:1 on the canvas |
| After Dark | `teal` | `rgb(12 7 16 / .9)` near-black | Friday still leans amber |
| Plum | `plum` | `rgb(27 11 26 / .94)` | Hero scrims and footer |
| Antique gold | `agave` | `#cfa456` / `#e6c27a` | Eyebrows, hairlines on photos |
| Amber | `amber` | `#f0b24a` | Unchanged in role |
| Status | `success` `warning` `danger` | lifted for a dark field | |

Hero scrims, opacity variants (`bg-plum/92`) and `color-mix` utilities all follow automatically.

LCP element.

Re-generate after editing the script: `npx tsx scripts/generate-theme-art.ts`.

## Components

| Component | Where it renders | What it does |
|---|---|---|
| `ThemeRoot` | `SiteChrome` (site layout, preview) | The `data-theme` wrapper, preset numbers as CSS custom properties, `<html>` background, the client mirror for portals |
| `ThemeAtmosphere` | inside `ThemeRoot` | Fixed layers: two glow fields, haze, plaster texture, vignette, petals |
| `ThemeHeroLayer` | inside `Hero`, under the type | Two papel picado strings, left/right marigolds, haze, candle-light |
| `ThemeHeroBackground` | inside `Hero` | Replaces the reel only when the admin uploaded a hero background |
| `ThemeDivider` | homepage, twice | The ornament between Offerings → Bar and After Dark → Catering |
| `ThemeFooterLayer` | inside `Footer` | Corner clusters in a strip under the legal line (`lg+` only) |

All of it is server-rendered. The only client code is `ThemeAttribute` (12 lines) which mirrors the
attribute onto `<html>` so the mobile drawer, which portals into `<body>`, inherits the tokens.

## Effects

| Effect | Implementation | Period | Off when |
|---|---|---|---|
| Ambient glow | two fixed radial-gradient fields, `z-index: -1`, breathing scale/opacity | 16 s / 23 s | Glow off · reduced motion (frozen) |
| Haze | one fixed layer, `background-position` drift, no filters | 64 s | Glow off · reduced motion |
| Texture | fixed tile, `soft-light`, 16 % × intensity | — | Texture off · reduced transparency |
| Vignette | fixed radial gradient, in front of content, under the header | — | never (scaled by intensity) |
| Petals | 7 / 14 / 22 spans (3 / 6 / 8 on phones), fall + sway + spin | 16–30 s each | Petals off · Motion off · reduced motion |
| Papel picado drape | ±0.18° rotation; back string counter-phase | 9 s / 13 s | Motion off · reduced motion |
| Marigold drift | ±1.4° rotation, 1.5 % scale | 14 s / 17 s | Motion off · reduced motion |
| Parallax | scroll-driven animation on the hero art (`animation-timeline: scroll()`); progressive | — | unsupported browsers (art simply stays put) |
| Candle-light | hero radial glow with a slow irregular flicker | 5.5 s | Glow off · reduced motion |
| Photo treatment | `sepia(.16) saturate(1.08) contrast(1.05) brightness(.94)` on photographs in `main` | — | never |
| Lit type | wide, faint amber `text-shadow` on `.display` in `main` | — | never |

Intensity presets (`src/themes/registry.ts` → `PRESETS`) scale petal count, glow, texture,
vignette and edge-art size. The admin sees three words; the CSS sees four custom properties.

## Mobile behaviour

- Below 640 px: both marigold clusters move to the **top corners** under the banner (the right one
  mirrored), at 104 / 136 px, so the headline, body and both buttons are never covered.
- The banner scales to a 900 px string so the pennants stay legible rather than shrinking to
  confetti.
- Petal field drops to the preset's mobile count; texture opacity drops by a third.
- Below 1024 px the footer clusters and the footer strip are gone.
- No decoration is `position: fixed` except the atmosphere layers, which are pointer-transparent.
- Tap targets are untouched; every layer is `pointer-events: none` and `aria-hidden`.

## Accessibility

- Every text/background pair was re-measured against the new surfaces (table above).
- `prefers-reduced-motion`: petals hidden, every animation removed, parallax off; the art is still
  there, still.
- `prefers-reduced-transparency`: texture and the secondary glow are removed.
- `color-scheme: dark` on the root so form controls match.
- Decorative images carry `alt=""`; the admin marks uploaded theme art decorative automatically.

## Admin-editable fields

From **Admin → Seasonal look**:

- On / off, and the dates it is on (Chicago time).
- Five switches: background texture, ambient glow, floating petals, decorative edges, motion.
- Intensity: Subtle / Standard / Full.
- Eight artwork slots, each optional: hero background (image or video), background texture, top
  decoration, left decoration, right decoration, foreground decoration, floating petal, section
  divider.

## Swapping the seasonal artwork

**Without code (the normal way):** Admin → Seasonal look → Artwork → *Choose a replacement* on the
slot. The file is stored in Photos & videos (tagged *Theme*) and the slot points at it by id.
*Use the built-in artwork* reverts. Sizes that work well:

| Slot | Shape | Suggested size |
|---|---|---|
| Top decoration | very wide, transparent, hangs from the top edge | 1800 × 270 |
| Left / right decoration | tall-ish, transparent, heavy toward the outer edge | 720 × 800 |
| Foreground decoration | transparent, heavy toward the bottom-left | 560 × 500 |
| Section divider | very wide, transparent, symmetric | 1400 × 175 |
| Background texture | square, tileable, mid-grey | 480 × 480 |
| Floating petal | tiny, transparent | 24 × 32 |
| Hero background | landscape photo or short muted video | 1920 × 1080 |

**Changing the shipped defaults (code):** edit `scripts/generate-theme-art.ts`, run it, commit
the files under `public/themes/halloween-dotd/`. Paths are declared in `src/themes/registry.ts`.

## QA record (2026-09-10)

Run against the local development database with Playwright at 1600, 1280, 834 and 390 px.

**Default experience.** With the row disabled the homepage HTML contains no `data-theme`, no
theme layer, no theme image; `<body>` is ivory and `<html>` transparent — pixel-identical to the
pre-theme build at 1280 px. Navigation, menu tabs, event pages, catering and private-event forms,
visit and careers all render and behave as before.

**Theme on.** Every public route (`/`, `/menu`, `/events`, `/events/[slug]`, `/catering`,
`/private-events`, `/visit`, `/careers`, `/legal/privacy`) at 1440 and 390 px: zero console errors,
zero failed requests, no horizontal overflow, zero decorative elements with pointer events. Hero
art clears the eyebrow/headline box at every width. Hydration: no warnings (the only client
component the theme adds sets one attribute).

**Admin, end to end** (`saveTheme` and friends through the real form): publish now → themed;
schedule in the future → not themed, status *Scheduled*, dates round-trip in Chicago time; schedule
containing now → themed; end before start → rejected with a sentence; switch back → default;
replace the divider → slot marked *Yours*; reset → *Built-in*. No console errors during any of it.

**Switches and presets** (DOM probe): Subtle 7 petals, Standard 14, Full 22; petals off → 0
petal elements; edges off → no hero art and no dividers; glow/texture off → those layers absent;
motion off → `data-motion="off"` and every animation name `none`. `prefers-reduced-motion`
→ petals hidden and all animations `none`.

**Performance.** Theme artwork totals 420 KB, all alpha WebP/SVG, `fetchpriority="low"` in the
hero and lazy elsewhere; the hero poster remains the LCP element. No added client JavaScript
beyond `ThemeAttribute`. Production build passes.

**Known pre-existing items, not caused by this work:** `src/lib/events.test.ts` has one test that
samples 52 weeks and exceeds the 5 s default timeout on slow machines; `/careers` logs Next's LCP
`priority` hint for its first photograph.

## Future theme creation

The engine is finished; a second look is content, not architecture. The minimum:

1. **Register the slug.** Add it to `THEME_SLUGS` in `src/themes/types.ts` and add an entry to
   `THEMES` in `src/themes/registry.ts`: name, short name, description, canvas colour, the eight
   asset slots with their default paths (or `null`), and default options. That single entry
   drives the admin choice list, the seed row, the migrate script, the preview route and the
   resolver.
2. **Write the stylesheet.** `src/themes/<slug>/theme.css`, scoped to `[data-theme='<slug>']`.
   Start by copying the token remap block and changing the values; the layer CSS can be reused
   as-is or rewritten. Import it next to the Halloween file in `src/app/(site)/layout.tsx` and in
   the preview route.
3. **Ship its artwork** under `public/themes/<slug>/` (any method; the generator script is a
   convenience, not a requirement).
4. **Seed the row** with `npm run content:seed` (local) and `npm run content:migrate -- --write`
   (Supabase). No migration is needed — `site_themes` already holds one row per slug.
5. **Point the admin at it.** Today `src/app/admin/theme/page.tsx` edits the one theme named in
   `CURRENT`; with a second theme, render the same `ThemeManager` per record (or add a selector).
   "One enabled at a time" is already enforced in `saveTheme`.

What does **not** change: the components in `src/components/theme/`, the resolver, the schedule
logic, the server actions, the preview route, the database, or any public page.
